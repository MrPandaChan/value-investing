## 完整结构

### 1. Header

```markdown
# 文章标题

> 来源：**文章来源/出版物全称**
> 链接：https://...
> 作者：Author Names
> 编辑：Editor Names
> 阅读时长：约 X 分钟
> 发布日期：YYYY-MM-DD
```

- 元数据以来源元数据或 README 为准；缺失项写“未知”，不猜测。
- 发布日期必须位于元数据块最后一行。若按模板完整填写六行，则第 6 行为发布日期，不得替换成采集引擎、正文分段、评论用户或排版插件信息。
- 无编辑时可省略“编辑”行；确无作者时写“未知”，不猜测。

### 2. TL;DR

使用 `## TL;DR`。写成 1-2 个紧凑自然段，不使用 bullet，回答：

1. 作者在试图回答什么关键问题？
2. 文章最重要、最可争辩的 1-2 个判断是什么？
3. 判断成立依赖什么机制、前提或取舍？
4. 本文最稀缺的证据、故事或张力是什么？

TL;DR 是全文的认知地图，不是“本文讨论了 A、B、C”的目录，也不能替代正文。

### 3. 核心结论

使用 `## 核心结论`。提炼 5-10 条真正支撑全篇的判断，按重要性排序。每条包含：

- 可被反驳的结论；
- 至少一层因果机制；
- 文稿中的证据、案例或适用边界；
- 观点归属：作者原意、文中受访者原意、多人共识或拆解者综合。

不要把同一观点拆成多条凑数量，也不要用“AI 很重要”“行业正在变化”之类正确废话。

### 4. 隐含推理与未明说暗示

使用 `## 隐含推理与未明说暗示`。提炼 4-8 条有证据的高置信度推论，优先寻找：

- 分散事实之间的跨段连接；
- 结论成立但没有明说的关键前提；
- 愿景与执行、增长与约束、安全与权力之间的取舍；
- 文章没有完整回答、回避或轻描淡写的论证缺口；
- 不同观点背后的时间尺度、目标函数或风险偏好差异；
- 作者经历、机构位置、利益关系如何影响其判断。

推荐采用“**推论—依据—边界**”结构。拆解推论不能伪装成作者原话，证据不足时写成待验证假设。

### 5. 详尽内容

使用 `## 详尽内容`。这是文章主体，也是质量差异最大的部分。

#### 5.1 信息预算

- 对有多个话题的文章，详尽内容原则上应占正文（不含 Header）的 **55% 以上**。这是防止“前面结论很长、正文只剩提纲”的最低警戒线，不是鼓励注水。
- `核心结论`和`隐含推理`只能压缩已经在正文讲清的材料，不能独占重要故事或证据。
- 章节数量和篇幅随信息密度变化。每章通常 2-6 个自然段；复杂主线可以更长，辅助章节可以较短，但不能只有一句提纲。
- 删除重复、套话和空泛升华；增加篇幅必须来自来源覆盖、具体证据、论证转折或必要机制。

#### 5.2 单章叙事骨架

每章不需要机械加小标签，但要尽量形成以下推进：

```text
作者为什么写 / 这个问题从哪里来
→ 作者第一层论证或叙事
→ 转折、反例、自我修正、引用对象回应或话题推进
→ 数字、案例、现场、亲历故事或独特措辞
→ 这段论证背后的机制
→ 没回答完的部分、成立边界或代价
→ 回扣该章命题并自然带到下一章
```

关键要求：

- 先把作者怎么说、为什么这样说讲清楚，再做拆解分析。单章中的拆解推演通常不超过约三分之一。
- 每个详尽章节至少有 2 项文稿证据；本章覆盖人物或亲历弧线时，至少 1 项必须是原始具体细节。
- 文章中的有效转折、编辑按语、引用对象回应、文末补充不是过场。它若改变论证、逼出前提或暴露缺口，必须写入。
- 直接引语只保留表达方式本身有价值且能够确认的短句；其余准确转述，不制造金句。
- 术语在首次出现时行内解释，让解释服务于故事，不另开词典。

#### 5.3 “烟火气”来自事实，不来自文学加工

优先保留以下材料：

- 作者或文中人物亲眼见到的场景、数量级和环境细节；
- 某次失败、争执、临时决定或偶然发现；
- “我不知道”“我错了”“我累了”等真实承认及其上下文；
- 关于同事、家庭、导师、用户或具体人物的片段；
- 能体现决策代价、性格、价值排序和认知更新的细节；
- 作者与采访对象、编辑、读者之间有来有回的瞬间。

禁止为了“更生动”虚构动作、表情、心理活动和现场氛围。烟火气必须来自来源正文。

#### 5.4 逻辑与推演工具

按材料需要选择，不机械打卡：

- 因果机制与中间环节；
- 激励、资源和物理约束；
- 单位经济、规模效应和反馈回路；
- 反事实与成立边界；
- 竞争者、客户、供应商和监管者的反应；
- 短期、中期、长期的时间尺度；
- 二阶影响和瓶颈迁移；
- 支持或推翻判断的可观察信号。

数据必须说明口径、对比基准和“所以呢”。类比只能帮助建立直觉，不能替代证据。

#### 5.5 章节组织

- 标题表达问题、判断或张力，如“需求无上限，带着两个前提”，不用“行业背景”“第一部分”等空标题。
- 同一话题散落多处时可以合并，但必须保留其中的论证顺序、关键转折和差异。
- 章节之间通过因果、转折或共同上层问题连接，不为追求“深度”强行合并彼此独立的文章弧线。
- 允许沿文章推进自然展开；“不按时间线机械切片”不等于删除文章的论证逻辑。

### 6. 总结升华

使用 `## 总结升华`。它由三部分组成：

#### 6.1 底层机制与可迁移判断

用 3-5 个自然段提炼正文之上的高阶连接：

- 哪个底层机制同时解释了多个章节？
- 作者同时持有哪些表面矛盾、实际带条件的判断？
- 哪个前提一旦失效，整套乐观或悲观叙事就会改变？
- 读者面对相似问题时应该观察什么变量，而不是照抄本文答案？

升华必须回到正文证据，包含至少一个边界或可观察信号。不要机械添加“人才、资本、愿景、世界观、人类文明”。

#### 6.2 各章一句话回望

使用三级标题 `### 各章一句话回望`。按照详尽内容的章节顺序，**每章恰好一句话**：

```markdown
- **一、章节名**：一句话说明该章回答了什么，以及它怎样推进全文主线。
- **二、章节名**：……
```

回望不是复制章节标题，也不是重新列一遍事实；它要让读者在一分钟内看见整篇文章的推进和整体感。回望条目数必须与详尽内容章节数一致。

#### 6.3 最后的收束

在回望之后用一个克制的自然段结束全文：合拢最重要的张力，指出最值得保留的问题或判断，不喊口号，不伪造确定性。

## 质量闸门

### 完整性

- [ ] 已完整读取来源元数据和完整来源正文，包括后半段、结尾、脚注、参考文献、图片说明、文末问答与延伸阅读。
- [ ] 来源元数据中每个非广告内容锚点（小标题、段落区间、图片说明、文末问答）都已进入账本，并可定位到详尽内容或一个有明确目标的重复合并项。
- [ ] 话题覆盖账本中的每个“展开”项都能在详尽内容定位到完整自然段，每个“压缩”项都能定位到承接句和目标章节。
- [ ] 没有为了压缩章节数丢掉独立的重要问题、故事、反驳、失败承认或人物片段。
- [ ] 对长且丰富的文章使用与内容匹配的 6-12 个章节，而非默认压成 3-6 章。
- [ ] 来源正文最后 20% 的实质话题已覆盖；存在治理/失败/人物结尾时，至少保留了一项判断材料和一项人物材料。
- [ ] 广告、赞助、推广或利益披露段落可排除；若其影响结论、利益披露或作者立场，必须进入隐含推理或边界。

### 结构与篇幅

- [ ] 最终文件严格包含 `## TL;DR`、`## 核心结论`、`## 隐含推理与未明说暗示`、`## 详尽内容`、`## 总结升华` 五个二级标题。
- [ ] 没有独立的术语/黑话章节；必要术语已在首次出现时行内解释。
- [ ] 对多话题文章，详尽内容占正文至少约 55%；不足时先检查遗漏，不用套话补长度。
- [ ] 各章一句话回望的数量、顺序和标题与详尽内容完全一致。

### 文章感与作者

- [ ] 重要章节交代了作者为什么写、如何论证、转折带来了什么变化。
- [ ] 来源存在现场、亲历故事、个人承认或人物细节时，正文确实保留，而非只剩抽象商业结论。
- [ ] 烟火气全部来自文稿，没有虚构动作、心理和氛围。
- [ ] 作者声音与拆解推论清楚分开，拆解分析没有压过原始文章。
- [ ] 对观点评论、人物专访、赞助内容，分别标注作者立场、利益关系和证据强度。

### 事实与论证

- [ ] 人名、数字、时间、案例和观点归属已回看来源正文；不确定信息未擅自补全。
- [ ] 核心结论都有机制、证据或边界，不是话题清单。
- [ ] 隐含推理采用“推论—依据—边界”，没有内幕臆测和心理揣测。
- [ ] 关键因果链没有跳步，重要数据说明了基准与含义。
- [ ] 无法化解的矛盾被保留，预测没有写成事实。

### 拆解质量

- [ ] 详尽内容是连贯 prose，不是 bullet 提纲或每章一小段的压缩稿。
- [ ] 每段都在增加事实、故事、论证推进、解释或边界，没有靠重复制造长文感。
- [ ] TL;DR、核心结论和总结升华没有大段重复。
- [ ] 全文可独立阅读，同时仍能让读者感到这是一篇真实存在的文章。
